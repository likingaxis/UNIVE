In the previous lecture, we started our journey on the transport network world, and we essentially said that this type of infrastructure is meant to interconnect different access networks that are located far away from each other. A possible scenario is where there are different access networks and we need a big infrastructure spanning over a wide geographical area to provide this transit service. Essentially, the main goal of a transport network is to let the traffic generated from an access network transit through this infrastructure and eventually be delivered to the destination network.

We also pointed out a set of main features and challenging peculiarities of this type of infrastructure. We can refer to them with different terms: transport network, Wide Area Network (WAN), and sometimes we refer to the network operator as a carrier. These are all terms that I will use interchangeably.

First of all, the traffic demand is high. The reason is that, differently from an access network that essentially exposes services to end users like us, a transport network instead has other networks as customers. It aggregates tributary flows—the traffic flows generated by end users—into an aggregated traffic demand that can easily reach hundreds of gigabits per second. Since the traffic demand is high, the capacity is also high.

Then we spent some time to understand what general topology is used in this context. Differently from access networks, where we generally use ring, point-to-point, or tree topologies, here we rely on a mesh. The reason is that a mesh topology offers path diversity, meaning there exist multiple paths to go from one point to another. This path diversity can be exploited in different ways: on one hand, to find good routes to deliver packets; on the other hand, in case of failure, we are more resilient because we can always switch to an alternative path. Path diversity can also be exploited to optimize performance in terms of balancing traffic demand, so that all the links and network resources are used in the best possible way.

In order to exploit all the possible advantages that path diversity offers, we need to deal with routing, which is yet another important aspect of a transport infrastructure. Routing becomes a relevant problem because we want to choose the best among alternative paths, react to failures by finding alternative routes, and distribute traffic in a better way over the available paths. Routing is a fundamental function for this type of network, while in access networks it is a minor functionality simply because the topologies used generally do not offer much path diversity. In a ring topology, which is essentially the only type of access network with a kind of diversity because we can go clockwise or counter-clockwise, rings are generally statically configured such that the clockwise direction is the primary path and the opposite direction is a backup path.

We also spent some time understanding the difference between a logical topology, a logical network, and a physical network. We started with the example of `traceroute` to realize that what we see when we run `traceroute` is a logical interconnection between nodes that can be many kilometers apart, as in our example with a router in Rome and another in Milan. From an IP perspective—from a logical point of view—these two routers are logically connected point-to-point. To make everything work from the client layer, the only management process we need to accomplish to let these two nodes communicate is to assign them IP addresses that fall into the same network prefix. For example, if we configure this link on the network 10.0.0.0/24, we can assign .1 to one interface and .2 to the other. From an IP perspective, by simply assigning IP addresses on the same network prefix, these two nodes will see themselves as directly connected.

The question is how they are actually physically connected. Between them, there is a physical infrastructure realized through optical fibers in a meshed topology. The physical layer provides connectivity to the higher layer. We generally refer to the logical layer as the client because there is a customer-provider relationship between higher-layer protocols and lower layers. The service that the physical underlay provides is at least connectivity. The physical network is configured to provide an end-to-end physical path between these two logical endpoints. When a packet needs to be sent from Rome to Milan, it is delivered to the physical optical network, propagates in the underlay, and reaches the other side of the connection.

One reason for adopting this paradigm is that different client layers can share the same physical infrastructure. Realizing a physical infrastructure that spans over a large geographical area, like a country or a continent, is very expensive. The physical infrastructure is singular and shared by different players that operate at a higher level, such as telco operators like Iliad, Vodafone, or WindTre. These players realize IP networks that are interconnected through the same physical infrastructure, which in general belongs to a single provider (in Italy, TIM).

Another property this optical underlay should have is transparency. On one hand, we want many clients to share the same physical infrastructure; on the other hand, we do not want to impose a specific technology on the client layer. If an operator wants to create an IP network on top of the physical optical network, it can do so; if someone else wants to realize an Ethernet network, they can as well. This layer is transparent to what it carries, much like IP packets: if you unwrap an IP packet, you can find different encapsulated protocols, such as TCP or UDP. From the viewpoint of the encapsulated protocol, the IP layer is transparent; whatever it carries, its working principle is the same. We want the same property for this optical network infrastructure, allowing different services to be realized on top of the same economic investment. In practice, both data networks (IP) and telephone networks are realized on top of the same underlay, avoiding the need to build parallel infrastructures for voice, data, and other services.

Now we need to understand better how the optical network works.

An optical network generally works according to a connection-oriented paradigm. A network can operate according to two different paradigms: connection-oriented and connectionless. In a connection-oriented environment, before two users can start transferring information, they must ask the network to establish a connection. There are essentially two phases: a request phase, and after the connection has been established, the information or traffic exchange phase. In a connectionless environment, this request is not required: if a user has data to transfer, it simply sends it out without notifying anyone. Nowadays, networks like IP networks are connectionless: if your laptop needs to send a packet, it transmits it without requesting the creation of a connection. On the contrary, TCP is a classical example of a connection-oriented protocol, where sender and receiver perform a three-way handshake to establish a connection before exchanging data.

Why do IP networks use a connectionless environment? In general, the time required to send a packet is very small compared to a connection setup procedure. Connection-oriented architectures are used whenever the traffic exchange phase lasts very long with respect to the setup duration. This is exactly our situation in the optical underlay: when we realize an IP link between two routers, that link is meant to stay in place for months, years, or decades. In this scenario, having a connection-oriented network is an ideal approach because the duration of the connection setup procedure is negligible compared to the lifetime of the connection being set up.

Creating a connection requires defining a way for users to share the available resources, which in this context is the capacity on the links. To make connections share links, the logical function we need is multiplexing. Whenever we want multiple users to share the same physical resource, we need multiplexing functionality. In connection-oriented architectures, the common approach is static multiplexing. Static means the network assigns a specific resource to a connection, and this assignment persists until one of the involved parties releases it.

For example, imagine a link that we divide into channels using a multiplexing technique, such as Time Division Multiplexing (TDM) or Frequency Division Multiplexing (FDM). In TDM, the time axis is divided into fixed-size slots (e.g., 1 millisecond or 1 microsecond). Individual time slots are organized into frames that repeat periodically over time. For instance, if a frame has four time slots, the structure repeats as slot 1, 2, 3, 4 of frame 1, then frame 2, and so on, dividing the link into four channels. Under static multiplexing, we assign the usage of a specific time slot to a given connection. If the network assigns the first time slot to a connection, data exchange for that connection occurs during the first slot of each recurring frame. Alternatively, in Frequency Division Multiplexing (FDM), the time axis is unslotted, and users are divided in the frequency domain. If the channel bandwidth is $W$, we divide the spectrum into different sub-bands, each centered around a carrier frequency, and uniquely assign a portion of the spectrum to a user for all time. Because the signals are separated in frequency, the receiver can recover the signal for a specific connection simply by using a frequency filter.

In optical networks, we use Wavelength Division Multiplexing (WDM). Conceptually, this is identical to frequency division multiplexing because frequency and wavelength are inversely proportional: as frequency increases, wavelength decreases. Once you fix the frequency, you can calculate the wavelength and vice versa. Conceptually, WDM can be understood as classical FDM with a different physical interpretation.

There are three main wavelength windows considered for optical communication. Today, we primarily use the window centered around 1.55 micrometers. This window is especially interesting because the absolute attenuation of the fiber is at its minimum, and the attenuation curve is flat. A flat curve means signal distortion is very small, making it a well-suited window for transmission.

From a physical standpoint, the signals sent in an optical network are light rays, which can be thought of as having different colors. An optical multiplexer takes incoming optical channels from different fibers, each carrying a light signal of a different color (for instance, red, green, and blue), and combines them into a single output fiber. That output fiber carries a single composite light ray containing all the wavelength contributions. In the spectrum, each line represents an optical carrier centered around a specific wavelength, functioning as an optical channel over the fiber. To multiplex users, the network operator uniquely assigns one of these wavelengths or colors to each connection request.

Consider the advantage of using WDM over TDM. The first generation of optical networks used time division multiplexing, whereas modern networks are based on WDM. A TDM multiplexer takes multiple incoming tributary flows, each with bit rate $B$ (e.g., 1 Mb/s), and interleaves them across time slots. The bit rate of the multiplexed output signal must equal $N \times B$, where $N$ is the number of flows. If we multiplex five users each generating 1 Mb/s, the output data rate is 5 Mb/s. In a transport network scenario with very high data rates and a massive number of tributary flows, the electronic card at the output of the multiplexer would require an extremely high clock frequency. We would quickly reach a limit where we cannot multiplex more users because we are bounded by electronic processing speeds.

With WDM, this problem is overcome. The bit rate of each tributary flow remains the same at the output because the users are separated in the frequency/wavelength domain rather than in time. From a physical perspective, incoming light rays produced by lasers on separate fibers enter the multiplexer and are redirected into a single output fiber, for instance using passive optical components like mirrors. There is no electronic bottleneck involved; the output carries the exact same light rays present at the ingress. When higher link speeds were needed historically, scaling via TDM proved extremely difficult electronically, and WDM emerged as the solution to overcome that limitation.

Now let us see how the physical interconnection between the routers in Rome and Milan is created across a mesh optical network where each link is divided into WDM optical channels (lambdas). Because it is a connection-oriented network, the first step is that the client issues a request to the server layer, specifying the endpoints to be interconnected (Rome and Milan). In the second step, the network performs connection setup, statically assigning an optical channel/wavelength on every link along the path. Once this is complete, the connection is up and the information transfer phase begins. Eventually, when the connection is no longer needed, a teardown operation occurs: the client notifies the network, and the allocated wavelengths are released for future users.

In the history of optical networks, there is a clear transition from first-generation to second-generation architectures. In first-generation optical networks, most functionality was implemented in the electronic domain. To understand this, consider the functionality of an optical node divided into two domains: an electrical domain and an optical domain.

In the electrical domain, signals are converted into digital binary strings. Concepts like IP source and destination addresses are logically meaningful because headers can be stored in memory, processed by CPUs, and manipulated easily. In contrast, in the optical domain, we deal purely with light rays: there is no practical way to store them in memory, and manipulating signal properties optically is extremely challenging.

If an intermediate node were a conventional router operating in the electrical domain, it would receive a packet, store it in a buffer, inspect the destination IP address, perform a longest-prefix match lookup in a routing table, identify the output interface, and forward the packet. All these operations—header inspection, buffering, and table lookups—are feasible only in the electrical domain. In the optical domain, they are not directly possible.

Because building optical switches was technologically difficult, early optical networks implemented all intelligent functions (such as switching and multiplexing) in the electrical domain. The optical domain was used solely for point-to-point transmission, leveraging fiber's low attenuation and immunity to interference, but failing to exploit the fiber's full potential bandwidth because nodes remained bounded by electronic speeds. In first-generation networks, client signals received in the electrical domain were multiplexed via TDM into an aggregate signal, converted from electrical to optical for fiber transmission, and then converted back into electrical format at the next switch for processing.

In second-generation optical networks, by contrast, switching and routing are performed directly in the optical domain. The fundamental design rule is to stay in the optical domain as much as possible, because avoiding optical-to-electrical conversions preserves performance and avoids electronic bottlenecks.

Looking at a typical optical network infrastructure, we find three main types of devices:
- Optical Line Terminal (OLT): The endpoint or termination of a point-to-point optical link. An OLT is the starting and ending point for a fiber link, housing all functionalities needed to transmit and receive light rays over the fiber.
- Optical Cross-Connect (OXC): The optical equivalent of a core switch or router. It terminates multiple input and output fibers, and its primary purpose is to dynamically redirect incoming light rays toward appropriate output ports directly in the optical domain.
- Optical Add-Drop Multiplexer (OADM): Functionally a smaller optical cross-connect, typically deployed at the edge of the infrastructure in metropolitan rings.

The overall infrastructure can be viewed as comprising two logical tiers:
1. The Core Backbone: A mesh topology spanning across cities and entire countries (such as TIM's national transport network in Italy), relying primarily on Optical Cross-Connects (OXCs) to provide diverse, redundant paths between regional endpoints.
2. The Metropolitan Edge: To provide connectivity across a city like Rome, each neighborhood has its own access network terminating at a Central Office (CO). All central offices within a metropolitan area are interconnected into an optical ring using Optical Add-Drop Multiplexers (OADMs).

In summary, OLTs terminate fiber links, OXCs perform switching in the meshed core backbone, and OADMs interconnect central offices in metropolitan rings.

At the boundaries of this infrastructure, we find the clients: for example, the IP router in Rome and the IP router in Milan, or other clients like SONET devices or Ethernet switches. They are served over the exact same physical infrastructure, illustrating technological transparency.

An end-to-end optical connection between clients is called a lightpath. Each lightpath is assigned a specific wavelength (lambda, or color) on each link it traverses. In this optical infrastructure, there is a fundamental constraint: the wavelength remains constant from end to end. The color of the client signal cannot be changed dynamically along the path.

This restriction is known as the wavelength continuity constraint, and it can lead to blocking. Blocking occurs when a client requests a connection, but the network cannot find an end-to-end path where a single wavelength is free on all traversed links.

For example, consider a network with nodes A, B, and C where several lightpaths are already established. The same lambda can carry different client signals over disjoint links; for instance, a red wavelength can be reused on different links without interference. Suppose we have four lightpaths already active using two available optical channels, red and green. When two new client routers request a connection between them, the network must find an end-to-end path where the wavelength remains constant on every link. If along one candidate path the green wavelength is occupied on the first link and the red wavelength is occupied on the second, neither wavelength is available end-to-end. If along an alternative path both wavelengths are likewise occupied, the network must refuse the request. This event is called blocking: the user asks for a lightpath, and the network replies that insufficient contiguous resources exist to satisfy the request.

Now let us examine the internal structure of these devices, starting with the Optical Line Terminal (OLT). An OLT is composed of modular elements:
- Optical-to-Electrical-to-Optical (O-E-O) converters, commonly known as transponders;
- Multiplexers and demultiplexers;
- Optical amplifiers.

The transponder interfaces with the clients (IP routers, SONET devices, Ethernet cards) on one side, and with the optical multiplexer on the other. Suppose a client router sends a packet. Some routers have optical transceivers capable of emitting an optical signal directly, but that signal is not centered on a wavelength controlled by the optical network operator. The transponder receives this optical signal on an arbitrary wavelength, converts it to the electrical domain, processes it, and converts it back into an optical signal on a designated WDM wavelength (for instance, converting a generic optical signal to a specific green carrier). This function is known as wavelength conversion, accomplished via an O-E-O conversion.

Furthermore, because the signal is temporarily in the electronic domain, this is the ideal point to add operational overhead. The optical network encapsulates the client packet into an Optical Transport Network (OTN) frame. Much like encapsulating a TCP segment into an IP packet and an IP packet into an Ethernet frame, the client packet is encapsulated into an OTN frame with an added header. This header contains fields that enable services such as link monitoring and error control. Rather than simple error detection like the IP checksum, OTN utilizes Forward Error Correction (FEC), an encoding technique capable of both detecting and correcting binary transmission errors. Finally, the electrical signal modulates a laser to produce an optical output on the assigned wavelength.

A transponder is traditionally a static device: its output wavelength cannot be changed dynamically. Once configured to transmit on a specific wavelength, it will consistently emit that wavelength. This provides important context for the blocking scenario: each active wavelength channel at an OLT requires a physical transponder. If an OLT is equipped with only two transponders, only two wavelengths can be transmitted. Transponders are expensive devices, costing roughly between €20,000 and €40,000 each. An optical grid can support up to 96 channels per fiber; fully equipping an OLT to utilize all 96 wavelengths would cost between €20,000 and €40,000 multiplied by 96—amounting to several million euros per device. In practice, resource constraints and wavelength blocking arise not primarily from technological limitations, but from economic cost.

Next are the multiplexer, demultiplexer, and optical amplifier. Multiplexing is performed via wavelength division multiplexing: transponders emit light rays with different wavelengths, which are combined into a single optical fiber containing all wavelength contributions, for example using passive optics and mirrors. In the opposite direction, a demultiplexer receives a composite light beam and separates it into individual colors. This is analogous to the cover of Pink Floyd's *The Dark Side of the Moon*, where a light ray hits a prism and splits into its component colors. This reflects how optical domain operations are constrained by what is physically achievable with passive optical physics, unlike the electrical domain where digital signals can be processed arbitrarily by CPUs. The optical amplifier simply boosts the power of the transmitted optical signal.

In some situations, a client is directly interfaced with the multiplexer or demultiplexer without passing through an external transponder. This occurs when the transponder is already integrated into the client equipment itself—for example, if a client interface card already generates an optical signal at the exact lambda assigned by the network operator.

Finally, an OLT includes a component known as the Optical Supervisory Channel (OSC). The OSC is powered by a dedicated transponder that injects a dedicated management wavelength, $\lambda_{\text{OSC}}$, alongside the user data channels ($\lambda_1, \lambda_2, \lambda_3$). The OSC is not meant to deliver user traffic; it is dedicated to monitoring the operational health of the physical infrastructure. For example, by monitoring the optical power of the supervisory channel, the operator can detect if a fiber cut has occurred and locate exactly where the break is located.
